Pipex — Résumé du projet
1️⃣ Partie obligatoire (Mandatory)

Nom du programme : pipex
Fichiers à rendre : Makefile, *.h, *.c
Arguments :

./pipex file1 cmd1 cmd2 file2


Fonctions externes autorisées :

open, close, read, write, malloc, free, perror, strerror, access, dup, dup2, execve, exit, fork, pipe, unlink, wait, waitpid

ft_printf ou équivalent codé par toi

Libft autorisée

Objectif

Reproduire exactement le comportement du shell :

< file1 cmd1 | cmd2 > file2

Exemples
./pipex infile "ls -l" "wc -l" outfile
# équivalent à < infile ls -l | wc -l > outfile

./pipex infile "grep a1" "wc -w" outfile
# équivalent à < infile grep a1 | wc -w > outfile

Règles

Makefile fonctionnel, sans relink inutile

Le programme ne doit jamais planter (segfault, double free…)

Aucune fuite mémoire

Les erreurs doivent être gérées comme le shell

2️⃣ Partie bonus

Important : Les bonus ne seront évalués que si la partie obligatoire est parfaite.

Bonus 1 : Multi-pipes
./pipex file1 cmd1 cmd2 cmd3 ... cmdn file2


Comportement équivalent :

< file1 cmd1 | cmd2 | cmd3 ... | cmdn > file2


Permet de gérer un nombre illimité de commandes connectées par des pipes

Bonus 2 : Here_doc
./pipex here_doc LIMITER cmd1 cmd2 file


Comportement équivalent :

cmd1 << LIMITER | cmd2 >> file


Différences par rapport au mode normal :

L’entrée est lue depuis stdin jusqu’au LIMITER

Le fichier de sortie est ouvert en append (>>) au lieu de trunc (>)

Minimum de 2 commandes (cmd1, cmd2)

3️⃣ Différences entre mandatory et bonus
Critère	Mandatory	Bonus
Nombre de commandes	2 seulement (cmd1, cmd2)	≥2, multi-pipes possibles
Entrée	fichier file1	fichier file1 ou stdin via here_doc
Sortie	fichier file2 (écrasé)	fichier file2 (append si here_doc)
Gestion pipes	1 pipe	N pipes (chaîne de commandes)
Gestion here_doc	Non	Oui (si premier argument = "here_doc")

⚠️ Même si tu codes directement les bonus, il faudra ajouter une condition pour distinguer le mode normal du mode here_doc, et pour gérer correctement l’ouverture du fichier de sortie et l’entrée de la première commande.

4️⃣ Conclusion / stratégie pour coder

Commencer par une structure flexible capable de gérer N commandes

Détecter si le mode est here_doc (argv[1] == "here_doc")

Adapter l’entrée :

Mode normal → file1

Here_doc → lecture stdin jusqu’au LIMITER

Adapter la sortie :

Mode normal → écrasement (>)

Here_doc → append (>>)

Boucle sur toutes les commandes pour créer les pipes et fork/execve

Gérer prev_fd et pipe_fd pour connecter les commandes

Toujours vérifier les erreurs et libérer la mémoire
